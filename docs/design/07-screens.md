# 7. 画面設計

## 7.1 UXの方針

### 契約者画面（高齢者を含む・スマホ中心）

- 基本の文字は **18px**、見出しは24〜28px。主なボタンは**高さ56px以上で全幅**、ほかの操作も48px以上。
- **1画面に主な操作は1つ**。重要な流れ（支払い・報告）はダイアログにせず、画面ごとの**ステップ形式**にする（戻るボタンと進捗「1/2」を表示）。
- 専門用語を使わない（「消込」「セッション」「決済手段」→「お支払い」「ログイン」など）。
- 状態は**アイコン＋文字＋色**で示す（色だけに頼らない）。✅ お支払い済み / ⏳ 確認中 / ⚠️ お支払いが遅れています。
- `confirm()` や `alert()` は使わない。確認は画面上に表示する。
- エラーは、何をすればよいかまで書く（例:「お名前と電話番号の下4桁が一致しません。登録したお名前を、スペースを入れずにお試しください」）。
- 金額は `¥3,000` のように3桁区切りで、大きく表示する。

### 管理画面（PCとスマホ）

- 情報量を優先してよい。表が主体。スマホでは表を横スクロールにし、主要な列は固定する。
- 取り消せない操作（承認、却下、免除、アーカイブ）は、確認用のダイアログを出す（shadcn の AlertDialog）。
- 保存が終わったらトーストで知らせる。

### 共通

- デザインのトーン: 落ち着いた白地に藍色のアクセント（旧UIの indigo を踏襲）。フォントはシステムの日本語フォント（`-apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`）。数字は `tabular-nums`。
- フォームは `<form action={serverAction}>` と `useActionState` を使う。送信中は `useFormStatus` でボタンを無効にし、文言を変える。
- ダークモードは対象外（v1）。

## 7.3 契約者の画面

### `/`（ログイン）

```
┌─────────────────────────────┐
│ 🅿️ ○○駐車場 お支払いページ         │  ← settings.businessName
│                             │
│ お名前                        │
│ [ 田中太郎            ]        │  18px, autocomplete="name"
│ 電話番号の下4桁                 │
│ [ ●●●● ]                    │  inputmode="numeric" maxlength=4
│                             │
│ [      ログインする       ]     │  56px 全幅
│                             │
│ QRコードをお持ちの方は、スマホの     │
│ カメラで読み取るだけでログインできます  │
│                    管理者の方 › │
└─────────────────────────────┘
```

実装は docs/design/09-ux-improvements.md の設計に沿っている。要点は次のとおり
（同ドキュメントの §9.4 が画面ごとの詳しい仕様）。

### `/portal`（ホーム）

- `lib/domain/portal-home.ts` の `deriveHomeState` が、複数のDB由来の事実を
  優先順位付きで1つの状態に絞り込む（`card_in_progress` → `rejected` →
  `needs_payment` → `waiting_confirmation` → `all_paid`）。**主なボタンは常に1つ**。
  ホームには常にこの1状態だけを大きく表示し、主状態の裏で別の月が確認中の
  場合だけ、補足として1行を添える。
- 支払期日（`settings.payment_due_day`。未設定なら月末）を過ぎていない
  `needs_payment` には「◯月◯日までにお支払いください」を表示する。過ぎて
  いれば ⚠️「お支払いが遅れています」に切り替わる。
- `card_in_progress`（Stripe Checkoutを開始したが完了していない）には
  ［お支払いを続ける］［やめる］の2つのボタンを出す。続けるとSessionの
  状態を取り直して再開・完了・期限切れのいずれかに振り分け、やめると
  Sessionを期限切れにして配分を解放し、その月をまた支払える状態に戻す
  （`resumeCardCheckout` / `cancelCardCheckout`、`lib/services/payments.ts`）。
- 初回だけ「ホーム画面に追加すると、次からすぐに開けます」を表示する
  （`components/portal/add-to-home-banner.tsx`。閉じたことは端末の
  `localStorage` に保存）。
- お支払いの履歴は直近3件だけをカードで表示し、［すべて見る ›］で
  `/portal/history`（全件）へ。

### `/portal/pay` → `/portal/pay/method`（お支払い、ステップ1/2・2/2）

- ステップ1「どの月の分をお支払いしますか？」: `method="get"` のフォームで
  `/portal/pay/method` へ送る（クライアントの状態を持たないため、ブラウザの
  ［戻る］で選択が消えない）。選択肢は大きなカード型のラジオボタンで、初期
  選択は「払う必要がある分」。支払う月が1つしかない場合はこのステップを
  飛ばす。
- ステップ2「お支払い方法を選んでください」: 💳 カード・スマホ決済
  （Apple Pay・Google Payも可・すぐに完了します）/ 🏦 銀行振込（確認まで
  1〜3日かかります）。前回使った方法を初期選択にし、設定で無効な方法や、
  有効な方法が1つだけの場合はカードを1枚だけ出す。カードを選んで押すと、
  Stripeへ移るまでの間「決済画面へ移動しています…」を全画面で表示する。

### `/portal/pay/transfer` → `/portal/pay/transfer/done/[id]`（銀行振込）

- 1ページの中で①「こちらへお振り込みください」（銀行・支店・口座・
  名義・金額。それぞれに［コピー］ボタン）②「お振り込みが終わったら」
  （振込名義・振込日 →［振り込みました］）の2つに区切る。振込名義の
  初期値はフリガナ（無ければ空欄のまま入力例と説明を表示）。
- 報告すると `/portal/pay/transfer/done/[id]` に遷移し、「✅ ご連絡
  ありがとうございます」「◯月分 ¥◯◯◯」「お振り込みを確認できたら、
  ホームに ✅ が付きます（通常1〜3日）」［ホームに戻る］を表示する
  （他人の入金IDを指定すると404）。

### `/portal/payments/[id]/complete`（カード決済の完了画面）

結果ごとに文言・ボタンを出し分ける（`fulfillCheckout` の戻り値と、
`canceled=1` かどうかで判定）。

| 結果                  | 表示                                                                                     | ボタン                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 完了                  | ✅ お支払いが完了しました / ◯月分 ¥◯◯◯                                                   | ［領収書を見る］［ホームに戻る］                                                    |
| 確認中                | ⏳ お支払いを確認しています。このままお待ちください                                      | なし（`components/portal/auto-refresh.tsx` が3秒ごと・最大3回まで自動で再読み込み） |
| 確認中（3回で未確定） | 確認に時間がかかっています。数分後にホームでご確認ください。二重に支払う必要はありません | ［ホームに戻る］                                                                    |
| 中止                  | お支払いを中止しました。**料金はかかっていません**                                       | ［ホームに戻る］                                                                    |
| 金額の不一致          | 金額の確認でエラーが発生しました。お手数ですが管理者へご連絡ください（設定の電話番号）   | ［ホームに戻る］                                                                    |

### `/portal/payments/[id]/receipt`（領収書）

同じタブで表示する（`target="_blank"` は使わない）。上部に
［‹ ホームに戻る］（印刷時は非表示）、ボタンは［保存・印刷する］。

### 見た目の共通ルール

- 本文は18px（`app/portal/layout.tsx` の外枠に `text-lg`）。ポータル配下では
  `text-sm` / `text-xs` を使わない（`test/portal-typography.test.ts` で静的に
  確認）。リンク・ボタンのタップ領域は `min-h-12`（48px以上）。
- 状態表示は `components/portal/status-badge.tsx` に集約し、アイコン＋文字＋
  色の3点で出す（✅ お支払い済み / ⏳ 確認中 / ⚠️ お支払いが遅れています /
  ❌ 確認できませんでした）。

## 7.4 管理画面

### 共通ヘッダー（`app/admin/layout.tsx`）

`sm` 未満（スマホ幅）では2段にする（1段目: タイトル＋［ログアウト］、2段目:
ナビを横スクロールできる1行）。メールアドレスはスマホ幅では非表示。`sm` 以上
は1行のまま。確認待ちの銀行振込があれば、「入金」ナビに件数のバッジ
（例: 入金 ②）を付ける。

### `/admin`（ダッシュボード）

- KPIカード（今月・JST）: 請求額 / 入金済み / 未収 / 滞納している人数（前月以前の未払いに加え、当月分も支払期日〈`settings.payment_due_day`〉を過ぎていれば含める）
- **要対応**: 確認待ちの振込（件数と、それぞれの［確認する］）、金額の不一致など（監査ログの警告）
- **入金マトリクス**: 行 = 契約者（アーカイブ済みは除く）、列 = 直近12か月。セル = ✅ 済 / ◐ 一部 / ⏳ 確認中 / ⚠️ 滞納 / ○ 未払い（今月以降）/ — 対象外 / 免 免除。セルをクリックすると、その請求の詳細が開く。

### `/admin/contractors/[id]`

- **基本情報**: 氏名、フリガナ、電話、区画、月額、契約期間、メモ →［保存］（月額を変えた場合は「未入金の請求にも反映する」のチェックを表示）。フリガナは予備ログインの照合にも使う（`login_kana_key`）ため、同じフリガナの在籍中の契約者がいれば警告を表示する
- **予備ログイン**: 氏名（`login_key`）の完全一致で見つからない場合、フリガナでも照合する。複数人が一致した場合は取り違えを防ぐため失敗扱いにする（失敗の文言は氏名の場合と同じ）
- **請求**: 月、金額、入金済み額、状態、操作（［入金を記録］［免除］）
- **入金**: 一覧 → 詳細へのリンク
- **ログイン**: QRの発行状況（発行日）、［ログインカードを印刷］［QRを再発行］［ログインを無効化］、ロック状態と［ロック解除］
- 下部: ［契約を終了してアーカイブ］（終了月を入力する）

### `/admin/contractors/[id]/login-card`（印刷用）

名刺からハガキ程度の大きさ。駐車場名、「田中太郎 様」、QRコード（SVG）、URL（手入力用の短い形）、「スマホのカメラで読み取ってください」、問い合わせ先。

### `/admin/payments/[id]`

入金の情報、配分（どの月にいくら）、振込名義・振込日、Stripe（Payment Intentのダッシュボードへのリンク）、状態の履歴（監査ログ）。pending の振込なら［承認］［却下（理由を入力）］。succeeded なら［領収書］。

### `/admin/settings`

セクションは4つ: 事業者情報（屋号、住所、電話、インボイス登録番号。`^T\d{13}$` で検証）/ 振込先口座 / 支払い方法（カード・振込のON/OFF、何か月先まで前払いを受け付けるか、支払期日〈1〜28日、未設定は月末〉）/ 税率（初期値10%）。
