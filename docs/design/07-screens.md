# 7. 画面設計

## 7.1 UXの方針

### 契約者画面（高齢者を含む・スマホ中心）

- 基本の文字は **18px**、見出しは24〜28px。主なボタンは**高さ56px以上で全幅**、ほかの操作も48px以上。
- **1画面に主な操作は1つ**。重要な流れ（支払い・報告）はダイアログにせず、画面ごとの**ステップ形式**にする（戻るボタンと進捗「1/2」を表示）。
- 専門用語を使わない（「消込」「セッション」「決済手段」→「お支払い」「ログイン」など）。
- 状態は**アイコン＋文字＋色**で示す（色だけに頼らない）。✅ お支払い済み / ⏳ 確認中 / ⚠️ お支払いが遅れています。
- `confirm()` や `alert()` は使わない。確認は画面上に表示する。
- エラーは、何をすればよいかまで書く（例:「お名前と電話番号の下4桁が一致しません。登録したお名前を、スペースを入れずにお試しください」）。
- 金額は `¥3,000` のように3桁区切りで、大きく表示する。

### 管理画面（PCとスマホ）

- 情報量を優先してよい。表が主体。スマホでは表を横スクロールにし、主要な列は固定する。
- 取り消せない操作（承認、却下、免除、アーカイブ）は、確認用のダイアログを出す（shadcn の AlertDialog）。
- 保存が終わったらトーストで知らせる。

### 共通

- デザインのトーン: 落ち着いた白地に藍色のアクセント（旧UIの indigo を踏襲）。フォントはシステムの日本語フォント（`-apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`）。数字は `tabular-nums`。
- フォームは `<form action={serverAction}>` と `useActionState` を使う。送信中は `useFormStatus` でボタンを無効にし、文言を変える。
- ダークモードは対象外（v1）。

## 7.3 契約者の画面

### `/`（ログイン）

```
┌─────────────────────────────┐
│ 🅿️ ○○駐車場 お支払いページ         │  ← settings.businessName
│                             │
│ お名前                        │
│ [ 田中太郎            ]        │  18px, autocomplete="name"
│ 電話番号の下4桁                 │
│ [ ●●●● ]                    │  inputmode="numeric" maxlength=4
│                             │
│ [      ログインする       ]     │  56px 全幅
│                             │
│ QRコードをお持ちの方は、スマホの     │
│ カメラで読み取るだけでログインできます  │
│                    管理者の方 › │
└─────────────────────────────┘
```

### `/portal`（ホーム）

表示する順番:

1. **あいさつ**:「田中太郎 様」「区画 A-3」「月額 ¥3,000」
2. **お知らせ**（ある場合だけ）: ⏳ 確認中の振込（◯月分）/ ⏳ コンビニでのお支払い待ち / ❌ 振込が確認できませんでした（却下理由）→ もう一度報告する
3. **お支払いが必要な月**: 滞納している月は ⚠️ を付けて上に並べる。今月分も含む。合計金額を表示し、主なボタンは［お支払いへ進む］
   - 支払う月が無い場合は「✅ お支払いが必要な月はありません」
4. **お支払いの履歴**: カードで表示する（日付 / 対象月 / 金額 / 状態 / ［領収書］）。表は使わない（スマホで読みやすくするため）

### `/portal/pay`

- ステップ1「何か月分お支払いしますか？」: 月のカードを古い順に並べる。タップすると、その月までを選ぶ（旧UIと同じ）。下部に固定のバーを出し「3か月分（2026年7月〜9月）合計 ¥9,000」を表示する。
- ステップ2「お支払い方法」: 大きな選択カードを2つ。💳 カード・スマホ決済（すぐに完了します）/ 🏦 銀行振込（確認に数日かかります）。設定で無効にしている方法は表示しない。
- カード → Server Action → Stripeへ移動（「決済画面へ移動します」とローディングを表示）

### `/portal/pay/transfer`

- ステップ1: 振込先（銀行・支店・種別・番号・名義）と金額を大きく表示し、［コピー］ボタンを付ける。「お振込みが終わったら、下のボタンを押してください」
- ステップ2: 振込名義（初期値はフリガナ）、振込日（初期値は今日）→［報告する］→ 完了画面「確認までしばらくお待ちください」

### `/portal/payments/[id]/complete`

- 完了: ✅「お支払いが完了しました」、金額、対象月、［領収書を見る］［トップへ戻る］
- コンビニ: 「お支払い番号はStripeからの画面・メールでご確認ください。お支払い後に反映されます」
- 確認中: ⏳（数秒後に自動で再読み込みする。最大3回まで）
- キャンセル: 「お支払いを中止しました」［トップへ戻る］

## 7.4 管理画面

### `/admin`（ダッシュボード）

- KPIカード（今月・JST）: 請求額 / 入金済み / 未収 / 滞納している人数
- **要対応**: 確認待ちの振込（件数と、それぞれの［確認する］）、金額の不一致など（監査ログの警告）
- **入金マトリクス**: 行 = 契約者（アーカイブ済みは除く）、列 = 直近12か月。セル = ✅ 済 / ◐ 一部 / ⏳ 確認中 / ⚠️ 滞納 / ○ 未払い（今月以降）/ — 対象外 / 免 免除。セルをクリックすると、その請求の詳細が開く。

### `/admin/contractors/[id]`

- **基本情報**: 氏名、フリガナ、電話、区画、月額、契約期間、メモ →［保存］（月額を変えた場合は「未入金の請求にも反映する」のチェックを表示）
- **請求**: 月、金額、入金済み額、状態、操作（［入金を記録］［免除］）
- **入金**: 一覧 → 詳細へのリンク
- **ログイン**: QRの発行状況（発行日）、［ログインカードを印刷］［QRを再発行］［ログインを無効化］、ロック状態と［ロック解除］
- 下部: ［契約を終了してアーカイブ］（終了月を入力する）

### `/admin/contractors/[id]/login-card`（印刷用）

名刺からハガキ程度の大きさ。駐車場名、「田中太郎 様」、QRコード（SVG）、URL（手入力用の短い形）、「スマホのカメラで読み取ってください」、問い合わせ先。

### `/admin/payments/[id]`

入金の情報、配分（どの月にいくら）、振込名義・振込日、Stripe（Payment Intentのダッシュボードへのリンク）、状態の履歴（監査ログ）。pending の振込なら［承認］［却下（理由を入力）］。succeeded なら［領収書］。

### `/admin/settings`

セクションは4つ: 事業者情報（屋号、住所、電話、インボイス登録番号。`^T\d{13}$` で検証）/ 振込先口座 / 支払い方法（カード・振込のON/OFF、何か月先まで前払いを受け付けるか）/ 税率（初期値10%）。

## 7.5 旧UIから引き継ぐもの・変えるもの

| 引き継ぐ                                                       | 変える                                                      |
| -------------------------------------------------------------- | ----------------------------------------------------------- |
| 「古い月から順に選ぶ」月選択カードと、下部に固定した合計のバー | ダイアログで進める流れ → ページのステップに                 |

| 領収書の見た目（印鑑風の「領収済」）                           | 税の内訳、連番、正しい支払方法、発行者のスナップショット    |
