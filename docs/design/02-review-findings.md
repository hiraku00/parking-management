# 2. 旧実装のレビュー結果

対象: v1（Next.js 16 + Supabase + Stripe, Vercel）。重要度: 🔴 高 / 🟠 中 / 🟡 低

## 2.1 セキュリティ

| #   | 重要度 | 箇所                                         | 問題                                                                                               | v2での対応                                                                             |
| --- | ------ | -------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| R1  | 🔴     | `app/portal/actions.ts` `reportBankTransfer` | `contractorId` をフォームの値から取っているため、**他人名義の振込報告を作れる**                    | 契約者IDは必ずセッションから取る。フォームに主体のIDを載せない（§05）                  |
| R2  | 🔴     | `createCheckoutSession`                      | 支払う月をサーバー側で検証していない。**支払い済みの月や契約期間外の月も決済できる**               | 請求IDで指定させ、「本人の・未払いの・確認待ちでない」請求だけを受け付ける（§06）      |
| R3  | 🟠     | `app/admin/layout.tsx`                       | `role !== 'owner'` のときに何もしていない。認可をRLSに丸投げしている                               | proxyでAccess JWTを検証し、さらに全ての管理系アクションで `requireOwner()`（§05）      |
| R4  | 🟠     | 契約者ログイン                               | 下4桁は1万通りしかないのに、試行回数の制限がない                                                   | QRログインを主にする。予備ログインにはIP単位のレート制限と、契約者単位のロックをかける |
| R5  | 🟠     | セッション                                   | 30日有効のJWTを失効させる手段がない                                                                | `session_version` による失効。QRを再発行したら既存のセッションも無効にする             |
| R6  | 🟡     | ログイン失敗の文言                           | 「契約者が見つかりません」と「電話番号が正しくありません」を出し分けており、契約者名の存在が分かる | 同じ文言にまとめる                                                                     |
| R7  | 🟡     | CSRF                                         | Server Actionの呼び出し元を検証していない（Next.jsの既定の保護に依存）                             | proxyでOriginを検証する（vinextの挙動に依存しない）                                    |

## 2.2 金額の正確性・データの整合性

| #   | 重要度 | 箇所               | 問題                                                                                                              | v2での対応                                                                 |
| --- | ------ | ------------------ | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| R8  | 🔴     | Stripe webhook     | 再送されると同じ入金を二重に登録する（冪等でない）                                                                | 状態遷移ガード付きの冪等な batch ＋ `stripe_events` による重複排除（§06）  |
| R9  | 🔴     | 入金判定           | 金額に関係なく、`succeeded` の入金が1件でもあればその月を支払済み扱いにする。**一部入金でも完済扱いになる**       | 請求に対する配分額の合計で判定する                                         |
| R10 | 🟠     | 複数月のカード決済 | 合計額を `Math.floor(total / 月数)` で割って各月に記録するため、端数が消える                                      | 請求ごとに配分額を持つ。入金は1件で、配分が複数                            |
| R11 | 🟠     | 料金の変更         | 未払い月の金額を毎回その時点の月額から計算しているため、料金を変えると過去の請求額まで変わる                      | 請求を実体化し、請求した時点の金額で固定する                               |
| R12 | 🟠     | 手動消込           | 月ごとに別々のServer Actionを順番に呼んでおり、途中で失敗すると一部だけ登録される。金額はクライアントから送られる | 1回の操作を1つの batch（トランザクション）で処理し、金額はサーバーで決める |
| R13 | 🟠     | 契約者の削除       | 入金履歴があるとFK制約で削除できない。そもそも帳簿は保存が必要                                                    | 物理削除をやめ、契約終了とアーカイブにする                                 |
| R14 | 🟡     | `payment_method`   | 入力検証は `'other'` を許すのに、DBのCHECK制約が拒否する                                                          | Drizzleのenumで一元化する                                                  |

## 2.3 機能の不具合

| #   | 重要度 | 箇所                 | 問題                                                                                                                                                                               | v2での対応                                                             |
| --- | ------ | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| R15 | 🔴     | 事業者設定           | フォームは口座種別を `ordinary`/`current` で送るのに、入力検証は `普通`/`当座` しか許さない。**設定をいつまでも保存できない**。住所もサーバー側だけ必須になっている                | 入力検証のスキーマを1つにして、フォームとサーバーで共有する            |
| R16 | 🟠     | タイムゾーン         | `new Date().toISOString().slice(0,7)` はUTCで月を判定するため、**日本時間の毎月1日0〜9時は前月扱いになる**。サーバーの `toLocaleDateString` もUTCで表示される。振込日の初期値もUTC | `lib/domain/time.ts` で Asia/Tokyo に統一する                          |
| R17 | 🟠     | 領収書               | 振込で払った分の支払方法が「クレジットカード」と表示される（`stripe_session_id` だけで判定しているため）。発行日が入金の登録日になっている。番号がUUIDの先頭                       | 入金方法を正しく表示する。連番の領収書番号。発行日と取引日を分けて持つ |
| R18 | 🟠     | 領収書               | インボイス登録番号を表示しているのに、**税率と消費税額が無い**。適格簡易請求書の要件を満たさない                                                                                   | 税率（10%）と内税の消費税額を表示する（§06）                           |
| R19 | 🟠     | 決済完了の表示       | URLの `?success=true&months=...` を信じて「支払いが完了しました」と表示する。Webhookで確定する前に出てしまう                                                                       | 戻り画面でCheckout Sessionを照会し、実際の状態を表示する               |
| R20 | 🟠     | 管理画面のステータス | 契約期間外の契約者も「今月支払済」と表示される。「今月の支払済」の数字は契約者数ではなく入金の件数                                                                                 | 請求の状態から集計する                                                 |
| R21 | 🟡     | 振込報告             | 却下できない。取り消せない                                                                                                                                                         | 却下（理由付き）を追加する。契約者には理由を表示する                   |
| R22 | 🟡     | 氏名でのログイン     | 完全一致でしか照合しないため、全角と半角のスペースの違いで失敗する                                                                                                                 | NFKC正規化して空白を除去した `login_key` で照合する                    |
| R23 | 🟡     | 受領者名             | 領収書に表示するオーナーの電話番号を、どこからも編集できない                                                                                                                       | 設定画面に電話番号を追加する                                           |
