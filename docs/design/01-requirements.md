# 1. 要件

## 1.1 利用者

| ロール             | 人数     | 特徴                                                           | 使う端末   |
| ------------------ | -------- | -------------------------------------------------------------- | ---------- |
| オーナー（管理者） | 1        | 駐車場の所有者。契約者の管理、入金の確認、領収書の発行を行う   | PC、スマホ |
| 契約者             | 10名以下 | 高齢者を含む。IT用語に不慣れ。メールアドレスを持たない人もいる | 主にスマホ |

## 1.2 機能要件

### 契約者（ポータル）

| ID  | 要件                                                                                       | 優先度 |
| --- | ------------------------------------------------------------------------------------------ | ------ |
| C-1 | QRコードを読むか、氏名＋電話番号下4桁を入力してログインできる                              | Must   |
| C-2 | 未払いの月と金額（滞納・今月分）が一目で分かる                                             | Must   |
| C-3 | 古い月から順に、何か月分を払うかを選べる                                                   | Must   |
| C-4 | クレジットカード（Stripe）で支払える。Stripeで有効化すれば、コンビニ払いやPayPay等も使える | Must   |
| C-5 | 銀行振込の場合、振込先を確認し、振込後に報告できる                                         | Must   |
| C-6 | 支払いの状態（処理中・確認待ち・完了・却下）が分かる                                       | Must   |
| C-7 | 支払い履歴を見られ、領収書を表示・印刷・PDF保存できる                                      | Must   |
| C-8 | ログアウトできる                                                                           | Must   |

### オーナー（管理画面）

| ID   | 要件                                                                                         | 優先度        |
| ---- | -------------------------------------------------------------------------------------------- | ------------- |
| O-1  | Cloudflare Access 経由でログインする（パスワードなし）                                       | Must          |
| O-2  | ダッシュボード: 今月の請求・入金済み・未収の額、滞納者、要対応（振込の確認待ち）             | Must          |
| O-3  | 契約者と月の入金状況を表（マトリクス）で一覧できる                                           | Must          |
| O-4  | 契約者の追加・編集・契約終了（アーカイブ）ができる                                           | Must          |
| O-5  | 月額料金を変更できる（未請求の月から適用。未入金の請求にも反映するかを選べる）               | Must          |
| O-6  | 契約者ごとにログイン用QRカードを印刷できる。再発行すると古いQRは使えなくなる                 | Must          |
| O-7  | 契約者のログインを強制的に無効化できる                                                       | Should        |
| O-8  | 振込報告を承認・却下（理由付き）できる                                                       | Must          |
| O-9  | 現金などの入金を記録できる（一部入金にも対応）                                               | Must          |
| O-10 | 請求を免除（void）できる。理由を残す                                                         | Should        |
| O-11 | 入金の一覧を見られる。領収書を表示・再印刷できる                                             | Must          |
| O-12 | 事業者情報（屋号、住所、電話、インボイス登録番号）、振込先口座、使える支払い方法を設定できる | Must          |
| O-13 | 操作の履歴（監査ログ）を見られる                                                             | Should        |
| O-14 | 振込報告やカード決済の完了をメールで通知する（独自ドメインが必要。§1.4）                     | Could（v1.1） |

### 公開ページ

| ID  | 要件                     | 優先度                                       |
| --- | ------------------------ | -------------------------------------------- |
| P-1 | 特定商取引法に基づく表記 | Must（Stripe本番審査で求められることが多い） |
| P-2 | プライバシーポリシー     | Must                                         |

## 1.3 非機能要件

| 分類             | 要件                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| 可用性           | Cloudflare Workers / D1 のSLAに従う。休止しない（旧: Supabase無料枠の休止対策が必要だった）        |
| 性能             | 画面表示 p95 < 500ms（10名規模なら十分余裕がある）                                                 |
| セキュリティ     | カード情報に触れない（Stripe Checkout）。管理系は二重防御（Access＋アプリ内検証）。§05             |
| 正確性           | 金額はすべて整数の円。請求と入金は一致し、二重計上しない（DB制約と冪等処理で保証）                 |
| 監査性           | 金額に関わる操作はすべて監査ログに残す。領収書は発行時点の情報を保存し、後から変わらない           |
| 帳簿保存         | 入金・領収書のデータは物理削除しない（契約終了はアーカイブ扱い）                                   |
| アクセシビリティ | 契約者画面: 基本の文字は18px以上、ボタンは高さ48px以上、状態を色だけで伝えない、専門用語を使わない |
| タイムゾーン     | 業務日付はすべて Asia/Tokyo                                                                        |
| バックアップ     | D1 Time Travel（無料プランは7日、有料プランは30日）。任意でR2へ定期エクスポート                    |
| コスト           | Cloudflareはすべて無料枠の範囲に収まる見込み。Stripe手数料のみ                                     |
| 運用             | mainへマージしたらCIでテスト→migration→デプロイ→スモークテストまで自動                             |

## 1.4 対象外（v1ではやらない）

- 契約者向けのメールやSMSでの通知・催促。契約者のメールアドレスは管理しない
- 定期課金（Stripe Subscription）。毎月、契約者の操作で支払う方式を続ける
- 複数の駐車場や複数オーナー
- 区画（スペース）の在庫管理。区画名は契約者の属性として文字列で持つだけ
- Stripe返金の管理画面からの操作。v1ではStripeダッシュボードで返金し、状態は手動で記録する
- オーナーへのメール通知（O-14）。Cloudflare Email Service は送信元に独自ドメインが必要なので、ドメインを用意した時点で v1.1 として追加する
